# Entités JDR — carte IA (degré 1a)

> Système générique de gestion des « entités de jeu » (sorts, objets, monstres, classes, etc.). Toutes partagent un modèle de champs commun, des droits unifiés, et un pipeline d'affichage/édition standardisé côté front.

## Quand lire ce nœud

- Ajouter/modifier un type d'entité, un champ, une vue, une colonne de table.
- Comprendre les droits de lecture/écriture d'une fiche.
- Travailler sur les pages Index/Show/Edit d'une entité.

## Concepts clés

- **Champs communs** : `state` (`raw`/`draft`/`auto`/`playable`/`archived`), `read_level` (0-5), `write_level` (0-5), `created_by`, soft delete. Beaucoup ont aussi `official_id`, `dofusdb_id`, `auto_update`. Détail : [README](./README.md#champs-communs). L’état `auto` (proposition IA/script à relire) est dans le code ; le pipeline LLM reste cadré : [IA générative](../../IA/_ai.md). Libellé `playable` = **Jouable** (affichage, tooltip du point, action) — pas « Actif ».
- **Droits** : matrice rôle × état, puis `read_level`/`write_level`, l'auteur garde l'accès. Code : `app/Policies/Entity/BaseEntityPolicy.php`. Détail : [README](./README.md#droits).
- **Backend CRUD** : un contrôleur web par entité dans `app/Http/Controllers/Entity/` ; validation par Form Requests `app/Http/Requests/Entity/`.
- **Suppression** : `EntityDeletionService` (soft/restore/force + impact) ; API `EntityDeletionController` ; web `delete` → même service. UI : `ConfirmModal` + `delete-impact`.
- **Tables (lecture)** : API server-side TanStack via `app/Http/Controllers/Api/*TableController.php`, changement d'état via `EntityStateController`. Index front : vue **minimal** par défaut (`useTanStackTablePreferences` v4). Sélection de lignes (cases toujours visibles, IDs normalisés) pour CSV / PDF, indépendante des droits d’édition. Raccourcis : `useTanStackTableKeyboard.js` (ignorés pendant la saisie ; pas de Ctrl+N). Pas de panneau d’édition multiple. Filtres : menus select par défaut (`TanStackTableFilters.vue`, `resolveTableFilterLayout`) ; chips seulement si `ui.layout: "chips"`.
- **Registre front** : `resources/js/Entities/entity-registry.js` (modèle + descriptors + adapter par type ; `normalizeEntityType()` normalise singulier/pluriel).
- **Vues** : `minimal` | `line` | `text` | `full` | `edit`. Résolution dynamique : `resources/js/Utils/entity/resolveEntityViewComponent.js`. Conventions : rule `.cursor/rules/entity-views.mdc`. Sorts / capacités Minimal+Line : halo coloré par l’élément (`getElementGlassSurfaceStyle`, `entity-element-ring` : lueur in/out + filet 20 %, `--element-border-color` / dégradé `--element-border-image`) ; le fond glass reste le thème. Notes de règles : `spellTypeRuleNotes` (sorts), `consumableRuleNotes` / `itemRuleNotes` (conso, monture, soin hors combat, respec de caractéristique, durée jusqu’au repos long).
- **Monstres** : coquille `Monster` + stats/sorts/équipements/traits sur `Creature` ; sorts, équipements **et traits** liés filtrés `visibleToUser` ; PDF multi + `visibleToUser` ; Full affiche sorts/empty states, équipements seulement s’il y en a. `resolved-stats` : même visibilité que le monstre/PNJ lié, et objets brouillon exclus des totaux publics. Tri catalogue par nom via sous-requête (pas de JOIN `creatures`). `store` crée la Creature via `Creature::create` (totaux `null` = composition, pas la factory Faker) et aligne `state` sur la coquille.
- **PNJ** : coquille `Npc` (rôle `npc_role`, taille 0–5 via `CreatureSize`, `story`/`historical`/`age`, langues `npc_language`, panoplies, boutique) + corps `Creature` (nom, `location` string, hostilité, niveau, stats, sorts `creature_spell`, stuff `creature_item`, traits). Sorts, équipements **et traits** liés filtrés `visibleToUser` sur fiche / catalogue (comme les monstres) ; boutique, panoplies, scénarios et campagnes aussi ; classe et spécialisation liées filtrées (une classe brouillon ne fuit pas via un PNJ jouable ; un PNJ brouillon ne fuit pas via une boutique jouable). L’édition charge toujours toutes les liaisons. `state` de la coquille synchronisé sur la créature à la création / changement d’état. Pas de scrapping DofusDB. Kit porté : 1 objet / emplacement (2 anneaux) via `NpcEquipmentSlotValidator` ; types hors équipement refusés. Panoplies associées sans auto-remplir les slots. CRUD : `NpcController` (`store` crée la Creature via `Creature::create` si `name`, mêmes défauts de fiche que les monstres) ; catalogue Index **server-side** (`NpcTableController`) ; page CMS **Bibliothèques → PNJ** (`bibliotheque-npc`, `config/nav_menu.php`) ; vues Full/Line/Minimal/Edit alignées Monster sans panneau DofusDB. Fiche / catalogue / PDF : `visibleToUser` sur classe et spécialisation.
- **Classes (`breeds`)** : fiche / table / PDF **et page bibliothèque CMS** (`LinkedEntityShow`) filtrent sorts, capacités, traits et PNJ liés avec `visibleToUser` (un sort brouillon n’apparaît pas sur une classe jouable). Le menu Bibliothèques → Classes se déplie : une sous-page par classe hors archive (`pages:sync-bibliotheque-entities`) ; brouillon/brut/auto visibles MJ+ seulement. L’édition charge toujours toutes les liaisons.
- **Spécialisations** : fiche / table / PDF **et page bibliothèque CMS** filtrent sorts, capacités, traits, objets, consommables, ressources et PNJ liés avec `visibleToUser` (un sort brouillon n’apparaît pas sur une spécialisation jouable). Même règle de menu que les classes (hors archive ; brouillons MJ+). L’édition charge toujours toutes les liaisons.
- **Listes lourdes** : index items/monstres/PNJ/ressources/consommables/conditions/sorts en pagination serveur ; PDF multi filtré `visibleToUser` sur les entités concernées. Nested relations des classes et spécialisations (sorts/capacités) aussi.
- **Tableaux (query)** : `filters[k][]` (multi) ou `filters[k][min]`/`[max]` (plages) ; `InterpretsEntityTableFilters`. Niveau = range dual (`RangeDualCore`, bornes SQL). État = pastilles à droite de « Filtres », défaut Jouable. Types / rareté = menu select. Stats combat en **filtres à la demande** (bouton « Ajouter un filtre », pas un dump de sliders). Bonus équipements / panoplies : `filters[bonus][strength][min]` (`type: "picked-range"`) — liste de caractéristiques, puis min/max (objet plat ; panoplie = **somme des paliers**). Pas de filtre texte (recherche `search=`). Tri : alias UI→SQL (`item_type` → `item_type_id`) + `sort.field` colonnes. Défauts de filtres : uniquement si la clé n’est pas déjà posée ; pas de re-apply sur tout `filterOptions` (évite d’effacer la saisie). Overlay sort depuis un monstre : chips dans le payload nested (`SpellNestedPreviewSerializer`).
- **Objets (vue Colonnes)** : image, nom, niveau, type, rareté, bonus (`items.bonus`) ; description et résumé masqués. Filtre **état** = pastilles à droite de « Filtres », défaut `playable` (comme panoplies / conso). En-têtes : `column.tooltip`. Filtre Type : menu multi **sans pré-coche** (Tous). Recette (ressources liées) : catalogue / fiche lecture filtrés `visibleToUser` ; l’édition charge toute la recette.
- **Consommables** : filtre Type sans pré-coche (Tous). Recette : même filtre `visibleToUser` que les objets (édition non filtrée).
- **Ressources, monstres, sorts** : mêmes filtres type / race sans pré-coche. Recette d’une ressource (`recipeIngredients`) : catalogue / fiche lecture filtrés `visibleToUser` ; l’édition charge tous les ingrédients.
- **Registres de types** : page commune `/admin/content/types/{equipment|resource|consumable|race|spell}` (anciennes URLs `/entities/item-types` etc. redirigent). API `/api/types/*` (races, types de sorts) et `/api/dofusdb/*-types` : admin. Deux flags persistés : `show_in_catalog` (en jeu, registre admin) et `allow_scrap` (maj DofusDB). `decision` reste une colonne historique syncée sur les types objet. Déplacement de catégorie seulement item/resource/consumable. Boutons catalogues → cette page.
- **États (conditions)** : scrap Dofus en `raw` ; catalogue préfiltre hors Brut. Les sorts pointent vers les 5 états JDR `playable` (Pesanteur, Empoisonné, Étourdi, Ralenti, Affaibli) via `ConditionCanonicalMapper` ; jeton Dofus conservé (`canonical_condition_id`). Flags mécaniques en chips. Filtre dissipable = interrupteur (`boolean`). Les textes scrapés disent **dissipable** (plus **désenvoûtable**) via `KrosmozGameTerms`. Maintenance : `php artisan conditions:remap-canonical`.
- **Ressources** : fiche lecture (`ResourceController::show`) filtre objets, consommables, créatures, scénarios, campagnes et boutiques liés avec `visibleToUser` (un objet brouillon n’apparaît pas sur une ressource jouable). L’édition charge toutes les liaisons.
- **Panoplies** : pièces en vue texte + vignette d’équipements ; niveau du set = MAX numérique des pièces visibles (`computedLevel`, pas de colonne SQL) ; bonus par palier de pièces (`2p` / `3p`) via `buildCharacteristicEffectCell`. Catalogue : filtres niveau (`level` range dual), nombre de pièces (`items_count` range), types d’objets présents (`item_type_id`, sans pré-coche), **bonus** (`picked-range`, somme des paliers), état = `EntityState::options()` (pas dérivé des lignes) ; tri défaut `level` asc. Catalogue / fiche lecture : `items` eager-load `visibleToUser` (un brouillon lié ne fuit pas) **avec** `bonus`/`effect` (`ItemPanoplyPayload::linkedItemPreview`) pour le total set+pièces en Minimal déployé. Édition : `items` sans ce filtre (sinon un sync détacherait la pièce). Fiches **équipement** : `ItemPanoplyMark` + payload `panoplies[]` (`ItemPanoplyPayload`, eager-load table/show **filtré `visibleToUser` / `view`** — un objet jouable ne fuit pas un set ou une pièce brouillon). Édition : équipements puis bonus en tête (`PanoplyBonusEditor`, champs glass) ; recherche via `api.tables.items` (`EntityPickerCore`) ; droits en bas de page.
- **Ouverture fiche** : Afficher (Minimal / Line / Index / table CMS) → `EntityModal` full ; Agrandir (modal) ou Ctrl+clic → page Show. Éditer (options Minimal / Line / tableau) → page Modifier. Config : `entity-actions-config.js`.
- **Rareté** : 0 Commun, 1 Peu commun, 2 Rare, 3 Très rare, 4 Légendaire, 5 Unique — mêmes libellés filtres / vues / édition (`Resource::RARITY`, `RARITY_GRADIENT`).
- **Prix kamas** : ressources = prix Dofus (`price`), plancher **1 kama** une fois `playable`. Consommables / équipements : `price_calculated` (formule) + `price_custom` (ajustement) ; `price` = total. Équipement = Σ(bonus × `base_price_per_unit`) + 150×niveau + 200×rareté. Consommable = somme recette. Échelle de soins hors combat (11 paliers × pain / poisson / viande / potion) : JSON `database/seeders/data/entities/consumables/healing-out-of-combat.json`. Parchemins de caractéristique (respec, 4×6) : `characteristic-respec-scrolls.json`, sans recette, `price_custom` 1k/3k/5k/10k. Utilitaires : `utility-playable.json` (rappel 800, antidote 1500, bière/café, élixir Wakfu 3500, renaissance 10k, bouclier / PV temp). `ConsumableSeeder` après `ResourceSeeder`. Recette soins = 10 × ressource de palier (prix ressource = prix conso / 10). À la création d’un item (et si bonus/niveau/rareté changent), `Item::syncCalculatedPriceFromFormula` tourne **avant** `HasKamasPrice` pour que `price` suive le calculé. Actualiser (vue full / édition) et masse (`entities:recalculate-prices`) réécrivent le calculé et vident le custom **sauf consommables `playable`**. Recettes des items `playable` : les ressources liées passent en `playable` (`MarkPlayableItemRecipeResources`, `ResourceSeeder` après `ItemSeeder`) sans réécriture des champs Dofus, puis plancher 1 kama (`EnsureMinimumPlayableResourcePrice`).
- **Classes** : JSON `database/seeders/data/entities/breeds/*.json` (19 fiches, ids Dofus 1–18 et 20 ; Foggernaut = Steamer). `ClassBreedSeeder` / `ClassBreedSeederImporter` **avant** `CapabilitySeeder` puis `MonsterSeeder` puis `SpellSeeder` : upsert `dofusdb_id` / `official_id` / `name`, `auto_update = false`, voix du §2.3.1.
- **Passifs de classe** : JSON `entities/capabilities/class-passives.json` (19 capacités `is_passive`, `playable`). `CapabilitySeeder` / `ClassPassiveSeederImporter` : upsert sur `name` parmi les passifs du catalogue, liaison `breed_capability` (sans détacher les autres capacités).
- **Sorts de classe** : 24 sorts / classe (12 emplacements × 2 variantes). JSON `*-level-1.json` (niveau 1) + `*-progression.json` (niveaux 3–14). `SpellSeeder` / `ClassLevel1SpellSeederImporter` : `playable`, `auto_update = false`, upsert `dofusdb_id` / `official_id` ; catalogues d’une même classe fusionnés avant sync ; `target_type` optionnel (`trap`, `glyph`) ; les autres sorts de la classe passent hors grille (`character_level` 0). Les sorts d’invocation (`invoquer`) lient `spell_invocation` + `params.monster_id` via `monster_official_id` `jdr:summon:…`.
- **Invocations de classe** : JSON `entities/monsters/class-summons.json` (19 fiches `playable` : Osa / Sadida / Steamer + Double, Synchro, Malle, Repaire, Griffe…). `MonsterSeeder` / `ClassSummonSeederImporter` **après** `SubEffectSeeder`, **avant** `SpellSeeder`. Coquille `Monster` + `Creature` (8/12/16 PV, 1 PM, 3 PA) + 1 sort-créature (`category` créature). Coffre Enutrof = zone, pas une fiche.

## Fichiers pivots

- `app/Models/Concerns/HasKamasPrice.php` — sync `price` = max(0, calculé + custom) ; appelle `syncCalculatedPriceFromFormula()` si présent.
- `app/Policies/Entity/BaseEntityPolicy.php` — logique de droits commune (view/create/update/delete + matrice visibilité).
- `app/Http/Controllers/Entity/SpellController.php` — exemple de contrôleur web d'entité (pattern réutilisé).
- `app/Http/Controllers/Api/` — `*TableController`, `EntityStateController`, `EntityDeletionController`.
- `app/Services/Entity/EntityDeletionService.php` — soft delete / restore / force delete + récapitulatif d’impact.
- `resources/js/Entities/entity-registry.js` — point d'entrée front d'une entité.
- `resources/js/Utils/entity/resolveEntityViewComponent.js` — charge le bon composant de vue.
- `resources/js/Pages/Organismes/table/EntityTanStackTable.vue` — table d'index.
- `resources/js/Pages/Molecules/entity/<type>/` — composants de vue par type (`*ViewMinimal`, `*LineRow`, `*ViewText`, `*ViewFull`).
